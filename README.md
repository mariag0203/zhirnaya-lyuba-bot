# Бот-монитор «Жирная Люба» (Мосбилет → Telegram)

Telegram-бот следит за спектаклем «Жирная Люба» театра «Шалом» на [Мосбилете](https://bilet.mos.ru/event/381336257/) и присылает подписчикам уведомления:

- 🆕 **новый показ** появился в расписании: дата, время, ссылка на выбор мест (и когда откроется продажа, если она ещё не открыта);
- 🎫 **места на конкретный показ**: «13.10 (вт), 19:00 — появилось 4 места, от 1500 ₽». Сообщение приходит при переходе «0 мест → есть места» для этой даты. Повтор про тот же показ не чаще раза в `NOTIFY_COOLDOWN_MIN` минут (по умолчанию 10).

Бот **не покупает и не бронирует** билеты. Он делает три обычных GET-запроса раз в 90 секунд (не чаще раза в минуту, это ограничение зашито в код) напрямую с IP сервера, без прокси.

## Откуда бот берёт данные

Это те же запросы, которые делает сама страница спектакля:

| Что | Запрос |
|---|---|
| Карточка события (ID в билетной системе, общий флаг «есть места») | `bilet.mos.ru/api/newsfeed/v4/frontend/json/ru/afisha/381336257` |
| Все показы спектакля, включая распроданные | `…/afisha/381336257/occurrences` |
| Свободные места и цены по каждому показу | `tickets-external.mos.ru/api/widget/v2/event/<ebs_id>/performances` |

Отдельных страниц у показов на Мосбилете нет: все даты выбираются в расписании на странице события. Поэтому ссылка в уведомлении ведёт на неё, а в тексте указано, какую дату выбрать. Распроданные показы билетная система не отдаёт вовсе; для бота это означает «0 мест».

## Команды

- `/start` — подписаться и прочитать, что делает бот
- `/status` — что бот видит сейчас: время последней проверки (МСК), найденные показы и свободные места по каждому, ошибки
- `/subscribe`, `/unsubscribe` — включить или выключить уведомления

## Что бот сообщает администратору (`ADMIN_CHAT_ID`)

- при первом запуске — список показов, за которыми он начал следить;
- если несколько проверок подряд (`PARSE_ALERT_AFTER`, по умолчанию 5) в расписании нет ни одного показа или ответ сайта не разбирается, значит, скорее всего, сайт поменялся;
- если 5 проверок подряд сорвались из-за сети или ошибок сайта;
- раз в сутки в `HEARTBEAT_HOUR` (по умолчанию 10:00 МСК) приходит короткое «я работаю» с числом проверок за сутки. Если это сообщение не пришло, бот не работает.

## Настройка

```bash
cp .env.example .env    # и заполнить BOT_TOKEN, ADMIN_CHAT_ID
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python main.py
```

Все параметры с пояснениями перечислены в `.env.example`. Файлы `.env`, `bot.db` и `bot.log*` в git не попадают (см. `.gitignore`).

## Работа на сервере (bloxa-home)

Бот работает как служба systemd `zhirnaya-lyuba-bot`: запускается при загрузке и перезапускается через 30 с после любого падения.

Обновление с ноутбука, из папки репозитория в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\pack.ps1
```

Скрипт упакует код (без `.env`, базы и логов), скопирует его на сервер в `~/zhirnaya-lyuba-bot` и запустит `deploy/install.sh`. Тот обновит зависимости, проверит настройки и перезапустит службу. Файл `.env` на сервере остаётся прежним.

На сервере:

```bash
systemctl status zhirnaya-lyuba-bot          # работает ли
journalctl -u zhirnaya-lyuba-bot -f          # живой лог
sudo systemctl restart zhirnaya-lyuba-bot
tail -f ~/zhirnaya-lyuba-bot/bot.log         # тот же лог в файле
```

Лог пишется по московскому времени. `bot.log` ротируется: хранятся 5 файлов по 5 МБ. Журнал systemd ротируется сам.

Одним токеном может пользоваться только один экземпляр бота. Перед запуском на сервере остановите бота на ноутбуке.

## Проверка без сети

```bash
python -m unittest tests.test_mosbilet -v
```

Тест подменяет ответы сайта и проверяет, что бот находит новые показы, считает места по каждому показу, не повторяет уведомления чаще заданного интервала и пишет администратору, если разбор перестал находить показы.

## Структура

```
config/settings.py      настройки из .env
monitors/base_monitor.py цикл опроса, HTTP, ошибки, состояние для /status
monitors/mosbilet.py    показы и места на Мосбилете, уведомления
bot/handlers.py         команды
bot/notifications.py    рассылка
database/               SQLite: подписчики, показы, лог рассылок
utils/scheduler.py      запуск мониторинга и ежедневного «я работаю»
utils/timefmt.py        московское время
deploy/                 pack.ps1 (с ноутбука) и install.sh (служба systemd на сервере)
```
